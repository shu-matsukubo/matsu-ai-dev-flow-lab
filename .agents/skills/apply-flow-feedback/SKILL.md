# 提供能力

固定済みfeedback集合に対する人間承認済みの分類、根拠、関連付け、引き継ぎ、最終結果を、指定されたfileへ反映する。

## 適用条件

- 対象集合と処理計画が固定されている。
- 人間承認の証拠を取得できる。
- 更新対象、移動先、処理記録の内容が入力で確定している。
- 書き手に対象fileの更新権限がある。

## 入力

- 固定済みfeedback file一覧
- 人間承認済みの処理計画と承認証拠
- 分類、根拠、関連feedback、引き継ぎ先
- 最終結果の確定有無
- 更新前のfile内容と配置
- 更新後に期待する配置と整合条件

## 出力

- 更新した処理記録
- 移動したfileと移動前後のpath
- 更新しなかったfileと理由
- 固定集合の欠落、重複、予期しない追加の確認結果
- 反映失敗、未実施、remaining risk
- 外部成果物が必要な場合の未完了境界

## 責務外

- 評価案または人間承認の作成
- 未承認内容の反映
- 改善実装または新規要求の確定
- Issueの作成または更新
- 承認範囲外の共通file変更
- branch、Pull Request、工程状態の操作
- 担当Agentまたは作業順序の決定

## 能力固有の処理

入力の承認証拠、対象集合、更新前配置を照合する。既存履歴を上書きせず、承認された処理記録を追記する。必要な対応の完了と根拠が確定したfileだけをresolvedへ、対応不要の判断と根拠が確定したfileだけをdismissedへ移す。改善要求を引き継いだだけ、または最終結果が未確定のfileはpendingに保つ。

同じfileのwriterを一つに保ち、移動前後で固定集合の各fileが正確に一箇所だけ存在することを確認する。入力にない関連付けや分類を追加しない。

## 失敗・未実施・残るリスク

承認証拠、更新前revision、配置が入力と一致しない場合は変更せず失敗を返す。部分反映が起きた場合はfileごとの状態と復旧に必要な情報を示す。外部Issueや改善実装は反映完了に含めない。
