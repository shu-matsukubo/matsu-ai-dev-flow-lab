# 提供能力

要求が現在の設計境界と実装へ与える影響を複数観点で評価し、設計判断成果物または判断に必要な未確定事項を返す。

## 適用条件

- 分析済みの要求と受入条件を取得できる。
- 現在有効な設計と関連実装を直接確認できる。
- 評価範囲と対象外を識別できる。

## 入力

- 要求と受入条件
- 現在有効な設計文書
- 関連する実装、テスト、運用制約
- 既に確定した人間判断
- 成果物の書式

## 出力

- 観点ごとの影響判定と根拠
- 採用する設計判断、比較案、判断根拠
- 変更対象となる責務境界と依存方向
- 未確定な人間判断、選択肢、影響
- 要求の受入条件への設計上の寄与
- 未対象、未実施、残るリスク

## 責務外

- 未回答の設計判断の推測
- Task分解または実装
- branch、commit、Pull Request、Issue状態の操作
- レビュー、検証、提出
- 作業順序または担当Agentの決定

## 能力固有の処理

次の観点を要求、設計、実装の証拠へ照合する。

1. frontendとbackendの責務
2. service境界と依存方向
3. APIまたは公開contract
4. authentication、authorization、session
5. persistence、database、data ownership
6. security boundary
7. testing strategy、CI、quality gate
8. AI開発フロー
9. Agentと能力の責務

影響がない観点にも確認根拠を示す。影響がある場合は、現在の境界、変更後の境界、依存方向、代替案、移行上の制約を明確にする。要求から一意に決まらない重要事項は質問として返す。

## 失敗・未実施・残るリスク

設計または実装を取得できない場合は、推測せず不足する正本と影響を示す。未確認の観点、実装時に検証が必要な仮定、移行中の不整合リスクを結果へ残す。
