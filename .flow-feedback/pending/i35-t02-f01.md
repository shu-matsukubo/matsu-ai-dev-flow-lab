# Task公開前レビューとPR確認の順序が循環する

- 発生元Issue: `#35`
- 発生元Task: `35-02`
- 発生元PR: 未作成（公開前レビュー時点）
- category: `flow-contract`
- symptom: `coordinate-approved-tasks`と`publish-task-pr`はレビュー・検証合格後のTask PR公開を求める一方、`review-changes`はTask PR本文、base、受入条件根拠の確認をレビュー完了条件に含めている。独立Reviewerは実diffの再レビュー後も、Task PR未作成のため完全合格扱いにできないと報告した。
- impact: 公開前レビューだけでは公開前提を満たせず、Task PRを作らなければレビューを完了できない循環が生じる。Mainが公開可否とTask完了状態を一意に判断できず、追加のレビュー往復が必要になる。
- evidence: Task 35-02の独立ReviewerはP1解消と文章差分の妥当性を確認した後、「Task PRは依然として未作成のため、PR本文の`Refs #35`、base/head、Draft状態、Task PR固有の受入条件根拠を確認できず、Taskレビューを完全合格扱いにはできない」と報告した。対して`coordinate-approved-tasks`は「合格後」に`publish-task-pr`を使用すると定める。
- suggestion: 実diffを対象とする公開前branchレビューと、Draft Task PR作成後のmetadata・CI確認を別の明示的なレビュー段階として定義し、どの段階でTask記録をcompletedへ移すかを規則化する。
