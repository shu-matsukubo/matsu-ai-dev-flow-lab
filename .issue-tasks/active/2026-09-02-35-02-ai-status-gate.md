## 目的

Requirement Issueの作業開始ゲートと各工程完了時の人間承認待ちへの引き渡しを、Main・Worker・Reviewerおよび関連Skillの実行規則として一貫して適用する。

## 作業内容

- Requirement Issue作業の開始時に最新ステータスを取得し、6種類だけを抽出する規則を追加する
- `AI：作業可能`だけで現在のチャット指示がある場合に限り開始する
- 人間承認待ち、未付与、複数競合、永続情報との不整合では変更せず停止する
- AIによる`AI：作業可能`の自己付与を禁止する
- 要求分析、基本設計、タスク計画、最終成果物の完成時に対応する人間承認待ちへ切り替え、再取得して確認する
- 正式な引き渡しを行った同じ指示では後続工程へ進まない
- ステータス変更はMainだけが所有し、Worker・Reviewer・補助Skillは変更しない
- QA専用または工程別AIラベルを追加しない

## 対象外

- 新しいSkillまたは外部サービス
- GitHub ActionsによるAI自動起動、PR自動merge、Issue自動close
- Requirement Issue Form、repository既定branch、ラベル定義
- 自動検証の追加
- Frontend、Backend、API、認証、DBの変更

## 懸念事項

- 複数の工程Skillで規則が重複するため、開始条件・停止条件・引き渡し先の不一致を独立Reviewerが重点確認する
- Mainだけがステータス変更を所有する境界を補助Skillへ誤って広げない
- 過去チャットやラベルだけを承認証拠にする規則を残さない
