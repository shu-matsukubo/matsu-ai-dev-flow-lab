# レビュー基準

## 目的

成果物または差分のレビューで用いる共通の判断基準とfindingの表現を一意に定める。

## 適用対象

要求分析、設計、実装、テスト、作業記録など、承認範囲に含まれる成果物とその差分に適用する。対象ごとの要求、設計、完了条件を優先し、このReferenceだけでscopeを決めない。

## 判断基準

次の順に確認する。

1. 要求充足: 要求と受入条件を満たす根拠があり、対象外を混入させていないか。
2. 正しさ: 通常系、境界値、失敗時、部分成功時に意図した結果になるか。
3. 回帰: 既存契約、利用者、テスト、運用に予期しない影響がないか。
4. 責務境界: 現在の設計、依存方向、data ownership、単一writerを守っているか。
5. 安全性: secret、権限、入力、外部変更、破壊的操作を安全に扱うか。
6. 検証: 変更リスクに対応する検証があり、未実施と限界が明示されているか。

findingは次の重要度で分類する。

| 重要度 | 判断 |
|---|---|
| P0 | 直ちに重大な損失、漏えい、全面停止を生む。提出を止める必要がある。 |
| P1 | 要求を満たさない、主要経路が壊れる、重大な安全境界を失う。 |
| P2 | 条件付きの誤動作、回帰、保守上の明確な欠陥がある。 |
| P3 | 軽微だが具体的な品質改善であり、好みだけではない。 |

各findingには重要度、対象pathと最小範囲、観測事実、利用者または工程への具体的影響、必要な修正を含める。指摘がない場合も確認範囲、受入条件との対応、未確認事項、remaining riskを示す。推測は事実と分ける。

## 対象外

このReferenceはレビューを実行せず、担当Agentを選ばず、成果物を変更せず、検証や提出を開始せず、工程状態を遷移させない。
