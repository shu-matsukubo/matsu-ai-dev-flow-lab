# Task分解基準

## 目的

要求と設計を、承認・実装・レビュー・検証可能な単一責務Taskへ分解する判断基準を一意に定める。

## 適用対象

実装または成果物作成の範囲、依存関係、完了条件、Agent構成を提案するときに適用する。

## 判断基準

各Taskは単一の結果を持ち、次を識別できること。

- 安定したTask keyと自然な日本語の名称
- 目的と対象範囲
- 具体的な作業内容
- 対象外
- 依存対象、種類、ゲート、完了条件、現在の根拠
- リスクと前提
- 客観的な完了条件
- 寄与する受入条件
- 必要なレビューと検証
- Agent構成

Task間の依存は`hard`、`soft`、`ordering`を区別し、開始、完了、提出、取り込みのどこがゲートかを示す。循環依存や、複数Taskが同じ成果物を同時に所有する構成を避ける。

次の場合は分割を検討する。

- 成果物の責務または受入条件への寄与が独立している
- 異なる専門性やレビュー観点が必要
- 変更順序または外部依存が異なる
- 失敗時に独立して戻せる境界がある

次の場合は過剰分割を避ける。

- 単独では検証可能な結果を持たない
- 同じfileの同じ責務を往復して変更する
- 分割により暫定的な不整合を作る
- 管理コストだけが増え、独立した承認価値がない

Agent構成は規模だけでなく、security、不可逆性、public contract、複数境界、部分失敗、統合複雑性などの具体的リスクで判断する。

## 対象外

このReferenceはTaskを承認せず、Task記録やbranchを作成せず、Agentを起動せず、実装、提出、工程遷移を実行しない。
