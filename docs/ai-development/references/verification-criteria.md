# 検証基準

## 目的

成果物の検証項目、結果分類、証拠、未実施と残るリスクの共通基準を一意に定める。

## 適用対象

実装、文書、設定、運用記録を含む成果物へ適用する。要求、設計、変更リスク、利用可能な実行環境から必要な検証範囲を判断する。

## 判断基準

repository全体の共通品質ゲートは `sh scripts/verify.sh` とする。定義元はrootとworkspaceの`package.json`および[テスト戦略](../../quality/testing.md)であり、このReferenceへコマンド内容を複製しない。

変更リスクに応じ、次を追加候補として判断する。

- 変更した契約や分岐のUnit Test
- 複数componentまたはservice間のIntegration Test
- 設定、schema、生成物の整合性確認
- security、権限、secret、破壊的操作の否定経路
- 文書構造、リンク、責務境界の契約テスト
- 代表操作を再現するfixtureまたは手順

各確認結果は次のいずれかで記録する。

| 結果 | 意味 |
|---|---|
| Passed | 対象、実行方法、期待結果、実結果を確認できた。 |
| Failed | 期待結果を満たさず、失敗内容と再現根拠がある。 |
| Not Executed | 環境、権限、依存関係などの理由で実行していない。 |
| Remaining Risk | 成功した確認だけでは保証できない具体的なリスクが残る。 |

未実施は成功へ読み替えない。Dockerが必要な共通入口を実行できない場合は理由と代替確認を分けて記録し、共通品質ゲートをPassedにしない。検証証拠には対象revision、コマンドまたは確認方法、終了結果、主要出力を含める。

## 対象外

このReferenceは検証を実行せず、修正、再実行、担当割り当て、提出、工程遷移を決定しない。
