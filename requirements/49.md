# Issue #49 要求分析

## 元Issue

- [Issue #49: 承認ゲートを簡略化し、各工程をチャット内で完結できるフローにする](https://github.com/shu-matsukubo/matsu-ai-dev-flow-lab/issues/49)

要求原文とIssue登録前の補足は元Issueを参照し、この文書へ重複して正本化しない。

## 目的

要求分析と基本設計において、単に作業を継続するためだけの中間承認、ラベル切り替え、再依頼をなくす。人間の知識または意思決定が必要な事項は進行中のチャットで解消し、完成した工程成果物はPull Requestで最終確認することで、品質上必要な承認を維持しながら操作コストを下げる。

## 要件

### RQ-01 要求分析工程の完結

- 要求分析を開始した後、要求範囲または受入条件に未解決の人間判断がなければ、途中成果物に対する承認や追加の開始依頼を挟まず、要求分析書の完成とRequirement Analysis PRの作成まで同じチャットで進められること。
- 人間判断が必要な場合は進行中のチャットで具体的に質問し、回答を受けた後は新たな開始依頼や同じ判断への再承認を求めず、要求分析書とRequirement Analysis PRの作成まで再開できること。

### RQ-02 基本設計工程の完結

- merge済みRequirement Analysis PRを前提に基本設計を開始した後、未解決の人間判断がなければ、設計途中の案に対する承認や追加の開始依頼を挟まず、工程成果物の完成と設計PRの作成まで同じチャットで進められること。
- 設計判断が必要な場合は進行中のチャットで選択肢と影響を示して質問し、回答を受けた後は新たな開始依頼や同じ判断への再承認を求めず、工程成果物と設計PRの作成まで再開できること。
- 設計変更が不要な場合を含む工程成果物の具体的な表現方法は、PRを最終確認点とする承認境界を満たすよう後続の設計で定めること。

### RQ-03 承認の意味と境界

- 人間によるチャット回答は、質問で特定した意思決定について確定した判断として扱うこと。
- 回答済みの同一事項を、途中成果物の承認待ちなど別の形式へ置き換えて再承認させないこと。
- 要求分析と基本設計の完成成果物はPRを人間の最終確認点とし、AIはPRの作成後に人間による確認とmergeを待つこと。
- 人間の認知または意思決定を必要としない、単なる作業継続の許可を承認として要求しないこと。

### RQ-04 必要最小限の状態管理

- Requirement Issueの状態は、現在の工程、作業主体、または人間が確認すべき完成成果物を識別できる必要最小限の集合とすること。
- 要求分析案または基本設計案など、工程途中の成果物を承認するためだけの状態を設けないこと。
- 状態名、状態数、遷移の具体形は既存構成との整合を確認して後続の設計で決定し、Issue記載の候補名を確定値として扱わないこと。
- 状態は作業権と確認対象を示す補助情報に限定し、チャット上の回答、PRの内容、merge結果などの正本を置き換えないこと。

### RQ-05 関連する正本と実行規則の整合

- AI開発フロー文書、Agent指示、要求分析および基本設計に関わるSkill、状態判定と遷移の規則、関連テンプレートを、同じ承認境界と停止条件に整合させること。
- 廃止した中間承認を要求する記述または判定を残さず、どの入口から実行しても同じ工程を復元できること。

### RQ-06 後続フローとの接続

- 基本設計の成果物が人間により確認されmergeされた後、既存のタスク分解、実装、レビュー、検証、Task PR、Issue統合PRのフローへ接続できること。
- タスク分解以降の責務境界、品質ゲート、二階層PR、人間だけが行うmergeとIssue完了判断を、この要求によって不必要に変更しないこと。

### RQ-07 品質と安全な停止

- 質問を省略してよいのは、人間の知識または意思決定を必要とする未確定事項がない場合に限ること。
- 要求範囲、受入条件、設計判断または安全性に関わる未回答事項がある場合は、工程成果物を確定せずチャット内で質問して停止すること。
- 承認ゲートの簡略化を、AIによる自己承認、PRの自動merge、Requirement Issueの自動完了、または品質ゲートの省略へ拡張しないこと。

## 受入条件

- AC-01: 要求分析の開始後に追加の人間判断が不要な場合、中間承認または追加依頼なしで、同じチャット内においてRequirement Analysis PRの作成まで完了できる。
- AC-02: 要求分析中に人間判断が必要な場合、同じチャットで質問と回答を行った後、新たな開始依頼または同一事項への再承認なしでRequirement Analysis PRの作成まで完了できる。
- AC-03: 基本設計の開始後に追加の人間判断が不要な場合、中間承認または追加依頼なしで、同じチャット内において設計PRの作成まで完了できる。
- AC-04: 基本設計中に人間判断が必要な場合、同じチャットで質問と回答を行った後、新たな開始依頼または同一事項への再承認なしで設計PRの作成まで完了できる。
- AC-05: 要求分析案、基本設計案その他の工程途中の成果物について、単なる継続許可を得るための承認状態または再依頼手順が、現在有効なフローから除かれている。
- AC-06: チャットで回答済みの判断について、工程成果物の完成前に別形式の追加承認を要求しないことを、関連する文書、Agent指示、Skillおよび状態遷移規則から確認できる。
- AC-07: 要求分析と基本設計の完成成果物について、PRが人間による最終確認点であり、AIがmergeしないことを確認できる。
- AC-08: 基本設計成果物のmerge後に、タスク分解以降の既存フロー、責務境界、品質ゲートおよび二階層PRへ接続できる。
- AC-09: 定義された各状態について固有の工程、作業主体または完成成果物の確認対象を説明でき、工程途中の案だけを対象とする状態が存在しない。
- AC-10: AI開発フロー文書、Agent指示、関連Skill、状態判定・遷移規則、関連テンプレートの間に、中間承認、再開条件、停止条件またはPR確認境界の矛盾がない。
- AC-11: 追加判断の有無を含む要求分析と基本設計の4経路、回答済み事項の再承認防止、および状態遷移について、自動検証または再現可能な検証で期待する結果を確認できる。
- AC-12: 共通品質ゲートと変更リスクに応じた追加検証が成功し、未実施項目と残るリスクがIssue統合PRに記録されている。

## 制約

- 人間の意思決定が必要な事項は、選択肢と影響を理解できる形で質問し、回答なしに確定しない。
- 要求分析書と設計文書の正本、PRによる人間の最終確認、既存のレビューおよび検証水準を維持する。
- Pull Requestのmerge、branch削除、Requirement Issueの完了判断は人間だけが行う。
- タスク分解以降の既存フローは、簡略化した承認境界へ接続するために必要な整合を除き、変更対象としない。
- 人間向けの見出し、説明、記録は、技術上の正式名称と機械値を除き自然な日本語で記載する。

## 対象外

- 人間による判断または完成成果物の確認そのものを廃止すること。
- AIによるPRのmerge、Requirement Issueの完了、またはラベルだけを契機とする自動実行を導入すること。
- タスク分解以降の実装、レビュー、検証および二階層PRの責務を全面的に再設計すること。
- AI開発フローと無関係なアプリケーション機能、API、認証、永続化または画面を変更すること。
- チャット全文、個人情報、secret、credentialまたは実案件固有情報を成果物へ保存すること。

## 重要な人間判断

| 判断対象 | 採用した判断 | 比較・棄却した案 | 根拠 |
|---|---|---|---|
| 要求分析と基本設計の途中確認 | 人間判断が必要な事項だけを進行中のチャットで確認し、回答後は工程成果物のPR作成まで継続する | 途中成果物ごとに承認待ちへ遷移し、再依頼を受けて再開する | Issueの目的、期待するフロー、承認ルールに明記されており、形式的な操作コストを減らせる |
| 回答済み事項の扱い | 質問で特定した判断について承認済みとして扱い、同一事項の追加承認を求めない | チャット回答後に設計案などの別名目で再承認を求める | Issueの承認ルールが二重承認を明示的に禁止している |
| 完成成果物の確認 | 要求分析と基本設計の完成成果物はPRを最終確認点とする | 工程途中の案をラベルで承認する、またはPR確認を省略する | Issueの目的と補足が、品質を維持しながら承認をPRへ集約すると明示している |
| タスク分解以降の扱い | 既存フローへ接続し、責務と品質ゲートを維持する | この要求でタスク分解以降も全面的に再設計する | Issueの「タスク分解以降」に既存フローへ接続すると明記されている |
| 状態名と遷移の具体形 | 必要最小限という判定基準を要求として確定し、具体的な名称と集合は既存構成を確認する後続設計へ委ねる | Issue記載の候補例をそのまま確定値とする | Issueが候補を例示に留め、既存構成との整合を確認して決定すると明記している |
| 品質担保 | 人間判断の確認、PRによる成果物確認、レビューと検証は維持する | 承認と品質ゲートを一律に廃止する | Issueの補足が、承認をなくすのではなく必要な箇所へ集約すると明記している |

## 未確定事項

- 状態ラベルの具体的な名称、種類数、遷移表、および既存状態からの移行方法は、RQ-04の基準に従って後続の設計で確定する。
- 設計変更が不要な場合を含む基本設計成果物の記録形式とPR差分の持たせ方は、RQ-02およびRQ-03を満たすよう後続の設計で確定する。
- 具体的な変更対象ファイル、変更順序、検証手段、およびAgent構成は後続工程で決定する。
- 要求範囲または受入条件の確定に必要な未回答の人間判断はない。
